## 单元 1:纯 Agent 多轮基线(未训练 harness)

**尝试**:未训练 Qwen3-4B Agent(select+adapt,top-5 quality 检索),10k test 全量/子集,Guard 判定(仅 Unsafe 算成功)。

**结果**:

| 设定 | 样本 | ASR | avg turns |
|------|------|-----|-----------|
| 单轮(v1) | 1000 | 4.30% | 1.00 |
| 3 轮(v1) | 1000 | 9.10% | 2.89 |
| 5 轮(v1) | 1000 | 11.10% | 4.66 |
| 10 轮(v1,子集) | 200 | 12.50% | 9.21 |

**结论**:多轮提供增益但收益递减(4.3→9.1→11.1);失败样本几乎烧满全部轮次(avg turns 接近上限),说明未训练 Agent 的"反思"质量低。**这驱动了 observation 标准化(单元 3)**。

## 单元 2:经典基线对比(PAIR / AutoDAN)

**尝试**:PAIR、AutoDAN 各 100 条(前 100),SafeRL + Guard,与 Agent 同判定口径。

**结果**:直发有害 prompt 0%;PAIR **0%**(0/100,avg 9.92/10 迭代,基本烧满);AutoDAN **19%**(19/100,avg 7.68/10 代,成功批提前收敛)。

**结论**:SafeRL(安全对齐模型)+ Guard 是极硬组合,对直发/PAIR 完全免疫;DAN 模板+遗传搜索(AutoDAN)有效。**AgenticRL 的参照目标 = 超越 AutoDAN 19%**。

## 单元 3:Observation 标准化(v1 盲反思 vs v2 有信息反思)

**尝试**:env.py 在 history 中注入结构化字段(Guard 标签、Target refused、Attack/Target 摘要),让模型"看见"上次攻击与目标回复。

**结果**(3 轮,Guard 判定):

| 设定 | 样本 | ASR | 备注 |
|------|------|-----|------|
| v1 3 轮(盲反思) | 1000 | **9.10%** | 全量基准 |
| v2 3 轮(有信息反思) | 1000 | **7.00%** | 全量,同口径 |

**结论**:**v2 有信息反思反而更差(-2.1pp,全量确认非子集假象)**。对未训练模型,注入 Attack/Target 摘要信息过载,干扰决策。**RL 训练的 observation 设计决策:先用精简观察(v1 式);"模型学会利用丰富信息"可作为 RL 后的 ablation 方向**(信息在,训练后可能学会用)。

## 单元 4:Agent 版本矩阵(harness 设计空间消融)

**尝试**:5 个变体 + 1 个组合变体(设计见 TODO 版本矩阵),Guard 判定,与 AutoDAN 同批样本可比。

**结果**:

| 版本 | 设计 | 样本 | ASR | avg turns |
|------|------|------|-----|-----------|
| AV1 | Select+Adapt(基线) | 100(前 100) | 5.00% | — |
| AV2 | No-Skill(自由生成) | 100(前 100) | 18.00% | — |
| **AV2** | **No-Skill(自由生成)** | **1000(全量)** | **23.20%** | 2.71 |
| AV3 | Select-Only(原始 skill 内容) | 100(前 100) | 3.00% | — |
| AV4 | Beam-2(Select+Adapt) | 100(前 100) | 8.00% | — |
| AV5 | Similarity-Retrieval | 100(前 100) | 6.00% | — |
| **AV6** | **NoSkill + Beam-2** | **100(前 100)** | **35.00%** | 2.44 |
| AV2 | No-Skill 5 轮 | 100(前 100) | 22.00% | 4.42 |

同批参照:直发 0% / PAIR 0% / **AutoDAN 19%**(前 100)。

**结论(已修订,证据加强)**:
1. **skill-adaptation harness 对未训练模型是负资产**:AV2 自由生成全量 23.2% 远超 AV1(5%),且**已超过 AutoDAN 19%**
2. **Beam 是最大的杠杆**:AV6(NoSkill+Beam-2,3 轮)35.0%,接近 AV2 的两倍;多轮(5 轮无 beam 22%)远不及 beam(3 轮 35%)
3. **适配是负的,检索方式影响小**:AV3 3% < AV1 5%;AV5 6% ≈ AV1
4. **对 RL 的启示(定稿)**:**action space 采用 AV6 式(自由生成 × 每轮多候选)**,observation 用精简式(v1,见单元 3);RL 目标 = 在 35% 之上继续提升

## 单元 6:对话式(Agentic)主方法形态(核心结果)

**尝试**:消息累积的真实多轮对话(system → user 初始 → assistant 动作 → user 环境反馈 → …),每轮 1 次 policy 调用,反思隐含在对话中(conv_eval.py)。

**结果**(前 100 条,3 轮,Guard 判定;括号为无状态对照):

| 变体 | 对话式 ASR | 无状态 ASR | 差值 |
|------|-----------|-----------|------|
| no_skill(自由生成) | **25.00%** | 18.00% | **+7.0pp** |
| no_skill_beam-2 | **35.00%** | 35.00% | 0 |
| select_adapt | 5.00% | 5.00% | 0 |

**结论**:
1. **对话式形态显著提升自由生成**(18→25,前 100)——消息累积让模型的反思真正有效(与无状态重建相比)
2. **beam-2 在两种形态下都稳定在 35%**(上限收敛)
3. **主方法配置确定**:**对话式 no_skill 为 RL action space**(训练时单动作),评估时应用 beam-2 放大;**skill 候选注入确定是负资产**(5% 恒定),从主方法中移除
4. **全量确认**:conv_no_skill 3 轮全量 = **23.20%**(232/1000,avg 2.74 轮)——**RL 基线**;beam-2 评估可放大至 ~35%

## 单元 5:RL 训练链(ms-swift 4.3.2 GRPO)——✅ 验证通过

**尝试**:插件(对话式 gym env)+ 直调 python CLI + 4 卡布局修正;100 数据条、5 步冒烟。

**结果**:
- **5/5 训练步完成**:`num_turns=3.0`(多轮交互真实发生)、`rewards/gym_reward` 流入 GRPO、`train_runtime≈116s`
- 全链路:数据集 → swift rollout(8003)→ gym env(jailbreak_env)→ target/guard → reward → GRPO 更新 ✅
- reward 全 0 符合预期(小批量 4 生成全失败,23% 基线下正常)

**排障要点**(详系 LOG):NCCL 假失败根因 = 脚本在 source common.sh 后才声明 NUM_GPUS,GPU 布局错到 4,5,6,7(不存在)→ `CUDA_VISIBLE_DEVICES` 无效;修复 = `NUM_GPUS=4` 前置。

**结论**:**RL 训练基础设施就绪**,可进入正式奖励建模(单元 7 草案 R1→R2→R3)与 AgenticRL 训练(exp01/02/03)。

## 单元 7:奖励建模设计(草案,待链验证后实证)

**设计**(RL 三阶段,先简单后复杂):

| 阶段 | Reward | 理由 | 预期作用 |
|------|--------|------|----------|
| R1(链验证) | ASR only:成功=1.0,失败=0.0(env 累计 total_reward) | 与基线同口径,验证链路 | 确认奖励信号流通 |
| R2 | + 过程奖励:每轮尝试 +0.1 | 稀疏奖励缓解(4.3%→25% 基线仍有大多数失败组零奖励) | 鼓励多轮尝试 |
| R3 | + 效率:早期成功加权(1 - (turns-1)/max) | 对齐"快而准",抑制拖满轮次刷分 | 提升效率指标 |

**已知风险**(文献):对抗设置 GRPO 不稳定(AdvGRPO)、reward 稀疏致熵坍缩(PISmith)——R2 过程奖励是主要对策;若训练不稳定,退回首轮只做 R1 并调 beta/lr。

**判定标准**:训练后 ASR(对话式 no_skill,3 轮)vs 基线 25%(单)/35%(beam-2);并记录 skill 选择……不适用(no_skill),改为记录动作多样性/长度分布。

**状态**:草案;链验证(R1)是第一步。
